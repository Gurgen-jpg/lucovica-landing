# Design

## Context

Источник — `../LUCOVICA — Design System 2.0.html` (борды 01–05). Борды предполагают React + Radix Primitives + Tailwind + cva; в landing_v2 этого стека нет (см. `openspec/config.yaml`). Страницы собираются при билде из TS-функций, возвращающих HTML-строки (`bootstrap-platform`), клиентский код — модули на чистом TS, собираемые esbuild.

Из бордов переносятся без изменений: значения токенов (борд 05 `tokens.css`), типографическая шкала (02), шкала отступов и сетка (03), визуальные спецификации компонентов (04). Не переносятся: `tailwind.config.js`, `cva`, `@radix-ui/*`.

## Goals / Non-Goals

**Goals:**
- Один файл токенов, на который ссылаются все стили; нарушение — ошибка сборки.
- Примитивы с поведением уровня Radix (фокус, клавиатура, ARIA) без фреймворка, с прогрессивным улучшением.
- Витрина `/ds` для ручной и e2e-проверки.

**Non-Goals:**
- Тёмная тема сайта целиком (тёмные только отдельные блоки на `--lv-inverse`).
- Кастомный выпадающий Select с поиском — берём нативный `<select>` со стилизацией.
- NavigationMenu с выпадающими подменю — хедер плоский (см. `home-page`).

## Decisions

### D1. Примитив = шаблон + стиль + (опционально) поведение
Каждый примитив — папка `src/ds/primitives/<name>/`:
- `<name>.ts` — функция `(props) => string`, генерирует разметку с правильной ARIA-семантикой в исходном HTML;
- `<name>.css` — стили только через `var(--…)`;
- `<name>.client.ts` — поведение; навешивается на элементы с `data-ds="<name>"` функцией `init(root)`.

Клиентский вход `src/client/main.ts` один раз вызывает `init` всех примитивов для `document`. Почему так, а не web components: шаблоны рендерятся при сборке и не требуют JS для первого отображения; custom elements дали бы FOUC и зависимость от JS для разметки.

### D2. Прогрессивное улучшение
Исходный HTML — «всё открыто»: все панели вкладок, все ответы FAQ, все отзывы видимы. JS при `init` ставит на корень `data-enhanced` и скрывает лишнее. CSS скрывает неактивные панели только под `[data-enhanced]`. Так соблюдается требование «контент без JS» и SEO.

### D3. Dialog на нативном `<dialog>` + `showModal()`
`showModal()` даёт top layer, `inert` для остальной страницы и Escape из коробки. Поверх добавляем: возврат фокуса на открывший элемент, закрытие по клику на `::backdrop` (проверка `event.target === dialog`), блок прокрутки (`overflow: hidden` на `html`), анимацию через `@starting-style`/класс. Альтернатива — свой focus-trap на `div[role=dialog]`: больше кода и багов, отвергнуто. Поддержка: все целевые браузеры (Safari ≥ 15.4).

### D4. Accordion и Tabs — свой код, не `<details>`
`<details name>` дал бы эксклюзивность бесплатно, но в спеке требуется кнопка с `aria-expanded`/`aria-controls` и поворот иконки; поведение `name` в старых Safari отсутствует. Пишем ~60 строк на каждый по WAI-ARIA APG.

### D5. CSS: обычные файлы, бандлинг esbuild, префикс `ds-`
Классы в стиле `ds-button`, варианты — атрибутами `data-variant="outline"`, `data-size="2"` (замена `cva`). Все CSS импортируются в `src/styles/site.css` и бандлятся esbuild в один хэшированный файл. CSS Modules не берём: при SSG-шаблонах-строках сопоставление хэшированных имён усложняет код без пользы.

### D6. Запрет литеральных цветов — stylelint
`stylelint` с `color-no-hex`, `color-named: never`, `function-disallowed-list: [rgb, rgba, hsl, hsla]` для всех CSS, кроме `src/ds/tokens.css` (override). Запускается в `npm run lint` и в CI-проверке сборки.

### D7. Шрифты — `@fontsource`
`@fontsource/cormorant-garamond` (300, 400, 300-italic) и `@fontsource/jost` (300, 400, 500), подмножества cyrillic + latin, WOFF2 копируются в `dist/fonts` при сборке; `@font-face` с `font-display: swap` пишем сами в `src/ds/fonts.css`. Два основных начертания (Jost 300, Cormorant 300) — `<link rel="preload">`.

### D8. Монохромные фото
`filter: grayscale(1)` на `.ds-photo img` + `object-fit: cover`. В бордах это ручка «mono» со значением по умолчанию 1; выносим в токен `--photo-mono: 1` (`grayscale(var(--photo-mono))`), чтобы при желании вернуть цвет одной правкой.

## Risks / Trade-offs

- [Своя реализация a11y-паттернов может содержать ошибки, которые Radix уже исправил] → e2e-тесты с клавиатурой на витрине `/ds` + `@axe-core/playwright` на каждой странице.
- [`@starting-style` не везде поддерживается] → без него диалог просто появляется без анимации — допустимая деградация.
- [Монохром фото может не понравиться на живых страницах] → один токен `--photo-mono`.
- [Шрифты Cormorant/Jost тяжелее системного SF Pro] → только нужные начертания и подмножества, preload двух основных, `swap`.
