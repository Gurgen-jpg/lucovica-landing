# Spec Delta

## Purpose

Определяет приём анкет гостей LUCOVICA (`POST /api/welcome`) и то, в каком виде они доходят до мастера, включая обязательное выделение рисков для здоровья.

## ADDED Requirements

### Requirement: Request handling order
`POST /api/welcome` SHALL обрабатывать запрос в порядке: rate limit (3 запроса за 60 секунд с IP → 429 `{ ok: false, error: "Слишком много запросов. Попробуй чуть позже." }`); разбор JSON (ошибка → 400 «Ошибка запроса. Попробуй ещё раз.»); honeypot (`_hp` непустое → 200 `{ ok: true }` без уведомлений); валидация; отправка уведомлений.

#### Scenario: Fourth request limited
- **WHEN** с одного IP приходит четвёртая анкета за минуту
- **THEN** ответ 429

#### Scenario: Honeypot
- **WHEN** приходит анкета с непустым `_hp`
- **THEN** ответ 200 и уведомления не отправляются

### Requirement: Validation and normalisation
Сервер SHALL требовать: `name` непустое (до 100 символов), `phone` из 11 цифр, `privacy_consent === true`; иначе 422 `{ ok: false, error: "Заполни все обязательные поля." }`. Поля MUST нормализоваться: `visit_type` ∈ {new, back}; `address_form` ∈ {ty, vy, ''}; булевы — к boolean или null; строки обрезаются (drink, milk 50; extra_drink_wish 500; car_number 20; talk_mode 20; kid_age 5; элементы kid_needs 50; health_notes 1000; элементы contraindications 100; skin_notes 500; source 50; extra_notes 1000).

#### Scenario: Missing consent
- **WHEN** приходит анкета без `privacy_consent`
- **THEN** ответ 422

### Requirement: Response
При доставке хотя бы в один канал сервер SHALL отвечать 200 `{ ok: true }`, иначе 500 `{ ok: false, error: "Не удалось отправить данные. Попробуй ещё раз или напиши нам в WhatsApp." }`.

#### Scenario: Delivered
- **WHEN** приходит корректная анкета и Telegram доступен, а почта нет
- **THEN** ответ 200

### Requirement: Welcome message format
Уведомление SHALL иметь заголовок «🌿 Новая Welcome-анкета» или «🌿 Новая Welcome-анкета (повторный визит)» (тема письма «🌿 Welcome-анкета (новый|повторный) — <имя>») и блоки: Имя, Телефон, Обращение, Тип визита; ☕ напиток с молоком, сахаром, сливками и пожеланием; 🚗 парковка и номер; 🤫 общение; ребёнок, возраст и нужды; 🏥 противопоказания, загар, кожа; для повторного гостя — «Здоровье изменилось: да/нет» и комментарий о здоровье; «📍 Источник» (только для нового гостя); «💭 Пожелания». Значения опций MUST выводиться человекочитаемыми подписями (из того же источника, что и форма), а не идентификаторами.

#### Scenario: Milk label
- **WHEN** гость выбрал банановое молоко
- **THEN** в уведомлении указано «Банановое», а не `banana`

#### Scenario: Returning guest health change
- **WHEN** повторный гость отметил «Да, расскажу», «Период лактации» и комментарий «с марта»
- **THEN** уведомление содержит «Здоровье изменилось: да», «Период лактации» и «с марта»

### Requirement: Safety flags
Если среди противопоказаний есть критические (Беременность, Период лактации, Онкология, Эпилепсия, Приём ретиноидов / Роаккутана), уведомление SHALL начинаться с выделенного блока «⚠️ ФЛАГИ БЕЗОПАСНОСТИ» с их перечнем — в письме красным блоком, в Telegram — первыми строками сообщения.

#### Scenario: Pregnancy flagged
- **WHEN** гость отметил «Беременность»
- **THEN** письмо и сообщение Telegram начинаются с «⚠️ ФЛАГИ БЕЗОПАСНОСТИ» и содержат «Беременность»
