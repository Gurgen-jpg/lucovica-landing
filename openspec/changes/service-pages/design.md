# Design

## Context

Текущие страницы — 3 «полных» (по ~11 компонентов в `../landing/src/components/<slug>/`) и 2 «лёгких» (`complex`, `cert`). Большая часть секций структурно одинакова и отличается только данными. Секции цен, отзывов и FAQ уже сделаны в `home-page`.

## Goals / Non-Goals

**Goals:**
- Набор общих секций `src/sections/service/*`, страницы = данные + порядок секций.
- Цены зон и офферов JSON-LD — производные от `services.ts`.

**Non-Goals:**
- Новые тексты или переписывание SEO-контента — только перенос.
- Галерея «до/после».

## Decisions

### D1. Страница описывается данными
```ts
// src/content/pages/sugaring/index.ts
export default {
  slug: 'sugaring', name: 'Шугаринг', goalPrefix: 'sugaring',
  meta: {...}, hero: {...},
  sections: [comparison(...), steps(...), zones(...), composition(...), suitability(...), results(...)],
  priceCategories: ['sugaring-women', 'sugaring-master', 'sugaring-teen', 'sugaring-men'],
  reviews, faq, cta,
} satisfies ServicePage
```
`src/pages/sugaring.ts` вызывает общий `servicePage(def)`, который добавляет крошки, Отзывы, Цены, FAQ, CTA и JSON-LD. `/complex` и `/cert` используют тот же `servicePage` с пустыми `sections`/`reviews`/`faq`.

### D2. Общие секции
`breadcrumb`, `serviceHero`, `comparison` (таблица/карточки методов с плюсами и минусами), `steps` (нумерованные шаги — тот же паттерн, что «Ритуал» главной), `zones` (Tabs «Девушки/Мужчины» + сетка кнопок или статичный список), `featureList` (Аппарат/Состав/Метод — заголовок + 4 характеристики), `suitability` (две колонки «Кому подходит» / «Противопоказания»), `results` (4 показателя — паттерн «Студия в цифрах»), `serviceCta`.

### D3. Зоны ↔ прайс
Зона в контенте хранит `priceRef: { category, item }` вместо строки цены. Тест сборки проверяет, что каждый `priceRef` указывает на существующую позицию; иначе зона без цены — и предупреждение в выводе сборки, чтобы владелец увидел несопоставленные зоны.

### D4. JSON-LD `Service`
Хелпер `service()` из `bootstrap-platform` получает категории страницы и строит `OfferCatalog` с `Offer {name: "<категория> — <позиция>", price, priceCurrency: RUB}`; для electro — из тарифов по времени, для cert — номиналы.

## Risks / Trade-offs

- [Исправление цен зон меняет видимые цены на странице лазера] → владелец сверяет таблицу «зона → позиция прайса» перед публикацией (вывод сборки перечисляет несопоставленные зоны).
- [Унификация секций может потерять мелкие визуальные особенности старых страниц] → допустимо: визуал задаёт ДС v2, контент сохраняется.

## Open Questions

- Какие из зон без прямого соответствия в прайсе («Голени / Бёдра», «Зоны мини», «Плечи + руки») сопоставить с какой позицией — решает владелец при сверке; на код и структуру не влияет.
