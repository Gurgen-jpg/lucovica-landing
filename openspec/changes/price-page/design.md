# Design

## Context

Сайт — Next.js App Router + Tailwind. Публичные страницы лежат в группе `src/app/(site)/`, чей layout добавляет шапку, футер, плавающую кнопку и виджеты мессенджеров. Цены — единственный источник `SERVICES`/`ELECTRO_PRICES` в `src/lib/services-data.ts`. Форма записи — клиентский `LeadForm` (модальный диалог, принимает `defaultService` из `SERVICE_NAMES_FOR_FORM`). Корневой `src/app/layout.tsx` подключает Метрику и общий JSON-LD.

Основной сценарий — ссылка из Telegram-группы, открытая во встроенном браузере на телефоне.

## Goals / Non-Goals

**Goals:**
- Короткая, быстрая, мобильная страница: цены → запись / карта / сайт.
- Никаких цифр, продублированных из `services-data.ts`.
- Возможность дать отдельную ссылку на мужской прайс.

**Non-Goals:**
- Полный прайс всех позиций (он есть на главной и страницах услуг).
- Индексация в поиске: страница дублирует цены сайта, поэтому `noindex` и не попадает в sitemap.
- Изменение `LeadForm` или API.

## Decisions

**1. Роут вне `(site)`: `src/app/price/page.tsx`.**
Страница — «посадочная» для внешних ссылок, ей не нужны навигация и плавающие виджеты (они перекрывают закреплённую кнопку записи). Корневой layout с Метрикой и шрифтами сохраняется. Возврат на сайт — явная кнопка «Перейти на сайт» и логотип со ссылкой на `/`.

**2. Выбор позиций — конфиг ссылок на `services-data`, а не копия цен.**
`src/components/price/price-list.config.ts` описывает группы: `{ id, title, audience, formService, picks: { categoryId, name }[] }`. Функция `buildPriceList()` резолвит каждую ссылку в `SERVICES` и бросает ошибку, если позиция не найдена — переименование услуги в `services-data.ts` ломает сборку и тест, а не тихо убирает строку. Конфиг локальный (используется одной страницей) — RULE 2. Позиции внутри группы сортируются по цене по возрастанию. Электроэпиляция берётся из `ELECTRO_PRICES` целиком (4 позиции).

Выбор позиций (≤10 в каждой группе):
- Лазер, девушки: подмышки, верхняя губа, классическое бикини, голени/бёдра, глубокое бикини, руки, ноги + комплексы «Подмышки + Глубокое бикини», «Бикини + Подмышки + Ноги», «Всё тело».
- Лазер, мужчины: подмышки, спина, грудь, лицо, глубокое бикини, руки, ноги + комплексы «Подмышки + Спина», «Бикини + Подмышки + Ноги», «Всё тело».
- Шугаринг, девушки: все 9 позиций категории `sugaring-women`.
- Шугаринг, мужчины: все 7 позиций `sugaring-men`.

**3. Переключатель пола — WAI-ARIA tabs, оба списка в HTML.**
Обе панели рендерятся на сервере; неактивная скрыта атрибутом `hidden`. Клиентский компонент управляет `aria-selected`, стрелками ←/→ и хэшем: `#men` при загрузке выбирает мужскую вкладку, переключение обновляет хэш через `history.replaceState` (без прокрутки и без записи в историю). Электроэпиляция — вне вкладок, общая.

**4. Одна форма на страницу.**
Один экземпляр `LeadForm` в клиентском компоненте страницы; кнопки групп задают `defaultService` (`formService` группы, значение из `SERVICE_NAMES_FOR_FORM`), закреплённая кнопка — без предвыбора. `LeadForm` сам применяет `defaultService` при каждом открытии (эффект на `isOpen`) — так же, как в `Services.tsx`.

**5. Контакты — из `site-config`.**
`ADDRESS`, `CITY`, `YANDEX_MAPS_URL`, `HOURS_TEXT` переносятся в `src/lib/site-config.ts`; `Contacts.tsx` переходит на них. Ссылка на карты — `https://yandex.ru/maps/org/lucovica/72594546932/` (открывает карточку организации с маршрутом и отзывами; в Telegram на телефоне откроет приложение Яндекс Карт, если оно установлено).

**6. Метаданные для превью в Telegram.**
`title`/`description`/`openGraph` страницы — «Прайс-лист LUCOVICA», с минимальной ценой «от N ₽», вычисленной из списка. Картинка — общая `og-image.jpg`. `robots: { index: false, follow: true }`.

## Risks / Trade-offs

- Встроенный браузер Telegram может кэшировать превью ссылки — после первой публикации изменения заголовка видны не сразу. → Окончательный текст превью проверить до рассылки (@WebpageBot сбрасывает кэш).
- Новые цели Метрики не считаются, пока не созданы в кабинете. → Отражено в задачах.
