### 🔴 Критично: 0 визитов за последние 30 дней по API
Запрос `ym:s:visits/users/pageviews` за 2026-06-27…2026-07-27 вернул **totals: 0** по всем
метрикам, `total_rows: 0`. Код счётчика подтверждённо стоит на проде и совпадает по ID —
то есть технически данные должны идти. Возможные причины (нужна ручная проверка в кабинете):
- реального трафика на сайт действительно нет (маловероятно — есть активная кампания в
  Яндекс Бизнесе, см. раздел 3);
- блокировка `mc.yandex.ru` на уровне хостинга/CDN/WAF (Timeweb) или браузерными
  блокировщиками у большинства посетителей;
- `code_status: "CS_ERR_UNKNOWN"` в настройках счётчика — автоматическая проверка
  установки кода Яндексом не смогла подтвердить статус (само по себе не ошибка, но в
  сочетании с нулевыми визитами — тревожный сигнал).
**Рекомендация:** открыть в кабинете Метрики отчёт «Мониторинг» / «Реальное время» и
визуально зайти на сайт с разных устройств, проверяя, засчитывается ли визит.

**Проверено 2026-07-27 (сервер точно не блокирует):**
- `curl -I https://lucovica.ru/` — заголовка `Content-Security-Policy` нет, в коде нет
  `next.config.js`/`middleware.ts` с headers — сайт сам ничего не режет.
- `mc.yandex.ru/metrika/tag.js` и `mc.yandex.ru/watch/108773179` отвечают нормально
  (200 / 302 с верным ID) — сторона Яндекса и хостинга (Timeweb, Caddy) не блокируют.

**Значит проверять нужно на стороне посетителя/сети:**
1. DevTools → Network → фильтр `yandex` на живом сайте — ищем `blocked:csp` или
   `net::ERR_BLOCKED_BY_CLIENT`.
2. То же в режиме инкогнито без расширений (частая причина — адблокер у посетителя).
3. Зайти на сайт с мобильного интернета (не офисный Wi-Fi/VPN) и проверить
   «Реальное время» в кабинете Метрики.
4. Внешняя проверка доступности `mc.yandex.ru` из разных городов/провайдеров РФ
   (например check-host.net).
5. Сверить с access-логами хостинга в Timeweb за тот же период — если реальные заходы
   есть, а в Метрике 0, проблема на клиентской стороне, а не в отсутствии трафика.
